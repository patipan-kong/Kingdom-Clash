# Mobile UI และการควบคุม

## รูปแบบหน้าจอ

มือถือแนวนอนเป็นหลัก พื้นที่เกมเต็มจอ HUD ทับสนามโดยไม่ทำให้ผู้เล่นต้อง scroll ออกแบบ logical viewport 960×540 แต่ขยาย world view ตามสัดส่วนจอ ไม่ยืดภาพผิดสัดส่วน HUD ยึด safe area และขอบ viewport จริง

| ตำแหน่ง | เนื้อหา |
|---|---|
| บนซ้าย | HP, LV, XP |
| บนกลาง | Gold, Wood, Iron และเป้าหมายด่าน |
| บนขวา | Pause และ Minimap |
| ล่างซ้าย | Virtual Joystick |
| ล่างขวา | โจมตี Q/W/E/R |
| กลางล่าง | Build, Shop, Army |

เป้าสัมผัสอย่างน้อย 48 CSS px ตามพื้นที่จริง; ปุ่มโจมตีประมาณ 64–72 px ระยะขอบให้หลีกเลี่ยง gesture Android ต้นแบบต้องทดสอบจอเตี้ย ไม่ถือว่าตำแหน่งบน desktop ใช้ได้ทันทีบนมือถือ

## สัมผัส

ใช้ pointer ID แยกเดิน เล็ง และกด UI รองรับอย่างน้อย 3 นิ้ว ปุ่มต้อง consume input ก่อนส่งให้ world เสมอ Pointer cancel, lost focus และ scene shutdown ต้องปล่อย joystick และการเล็ง

แตะสกิลยิงที่เป้าหมายปัจจุบันหากเป็นชนิดที่อนุญาต; กดลากเพื่อเล็ง; ลากออกโซนยกเลิกเพื่อไม่เสียคูลดาวน์ สกิลล็อกเป้าหมายต้องมีเป้าหมายถูกต้องก่อนใช้

## Build Mode

แสดง Grid เฉพาะเขตสร้างและตำแหน่งตัวอย่าง เลือกอาคารแล้วแตะตำแหน่ง แสดงสีพร้อมข้อความเหตุผลหากสร้างไม่ได้ เช่น ทรัพยากรไม่พอ/พื้นที่ทับ/นอกเขต กดยืนยันก่อนหักเงิน มีปุ่มยกเลิกตลอดเวลา

เลือกอาคารที่มีอยู่เปิด HP, Upgrade, Repair, Demolish รื้อใช้การยืนยันเพื่อกันแตะพลาด ปุ่ม UI ไม่ทำให้ Hero เดินหรือยิง

## เวลาและกล้อง

Build และ Shop ใช้ timeScale 0.25 ในเกมคนเดียว; Pause ใช้ 0; ออกจากเมนูคืนค่าจาก state ไม่คูณ timeScale ทบกัน กล้องตาม Hero ขณะต่อสู้ Build Mode ลากดูสนามได้และมีปุ่มกลับหา Hero

Minimap แตะย้ายกล้องชั่วคราว ไม่สั่งเดินโดยอัตโนมัติ ขณะ Hero ตายกล้องดูสนามได้และแสดง timer ชัดเจน

## Portrait และเสียง

แนวตั้งแสดงหน้าขอหมุนจอและ pause simulation; กลับแนวนอนให้แตะดำเนินต่อ เสียงเริ่มหลัง gesture ของผู้เล่น มี volume และ mute บันทึกการตั้งค่า

## การเข้าถึง

ไม่ใช้สีอย่างเดียวสื่อฝ่ายหรือพื้นที่ห้ามสร้าง มีข้อความกำกับ ปรับขนาด UI และลดเอฟเฟกต์ได้ ปุ่มและข้อความสำคัญอ่านได้บนมือถือจริง
